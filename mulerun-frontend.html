Enterprise launch requirements

This document defines the minimum technical, legal, and operational requirements for enterprise production workspaces.

4.2 Identity and access

Before the first production workspace is created, the account owner must verify SAML 2.0 single sign-on and automated SCIM provisioning. Break-glass administrator access must be documented and tested during the pilot.

4.3 Data residency

Accounts serving European Union entities must select the EU storage region before initial data ingestion. Region changes after activation require a supervised migration.

4.4 Rollout sequence

  1. Execute the data processing agreement and complete vendor review.
  2. Configure SAML, SCIM, and approved administrator groups.
  3. Run a two-week pilot with at least 25 administrators.
  4. Approve migration cohorts after pilot acceptance.

Grounded answer

What are the requirements for our enterprise rollout?

96% GROUNDED 3 SOURCES 1.8s

The enterprise rollout has four gating requirements: SSO via SAML 2.0, automated SCIM provisioning, EU data residency, and a signed data processing agreement. SSO and provisioning must be enabled before the first production workspace is created.

Security review requires SOC 2 Type II evidence, encryption at rest using AES-256, and customer-managed key support for regulated accounts. The launch plan also identifies a two-week administrator pilot with at least 25 users before general availability.

Open dependency

Customer-managed keys are scheduled for release in October. Regulated accounts should not be migrated until this control is available.

For the rollout owner, the recommended order is: complete legal review, configure identity and access controls, validate regional storage, run the administrator pilot, then approve migration by cohort.
