Architecture

How a question becomes a cited answer.

Embeddings stay on this machine. The passages themselves leave when Jev scores them, when the writer drafts an answer, and when a separate checker reads that draft. The dashed line on the map is that boundary.

The whole path

Three lanes. Ingest builds the library. Query reads it. Control decides whether a new index may go live, and whether a weak search gets one more try.

When you upload a file

Ingestion is the slow path, and it happens once per file. The goal is a library the question path can trust.

What happensIn order
1

Check the file

Only PDF, Word, text, slides, and spreadsheets. Empty files and anything over 50 MB are refused.

↓
2

Read the text

PDFs keep their page numbers. Other formats are converted to text. Files with no readable text are rejected.

↓
3

Keep the headings

Markdown headings become a trail such as “Safety > Gloves,” so a citation knows which section it came from.

↓
4

Split into parents and children

A parent is about 2,000 characters: enough context to answer from. A child is about 400 characters: small enough to match precisely. Each parent also gets a short index card.

↓
5

Embed and publish

Children and index cards are written to the active vector index. The full parent text is stored beside it, not inside every vector. A run is logged: success or failure.

Why it is split this waySmall for search. Large for reading.
Child piece

Used to find the right spot. If we searched the whole chapter, the meaning would be too diluted.

Parent section

Shown to the model after a match. The model sees the paragraph around the hit, not a slice that ends mid-sentence.

Index card

A short heading-plus-lead summary, also searchable, for questions that match a title better than a sentence.

Chunking

The split style belongs to the index version. It changes on the next refresh, not on the next upload. Set CHUNKING_STRATEGY before refreshing.

When you ask a question

This is the path you feel in the chat. Status lines in the window follow these same stages: search, rerank, fetch, write, check.

About one question

The example we ran — “What is an attention mechanism?” — found 11 candidates, Jev kept 5 parents, and the check released a cited answer.

Search

Embed, then fuse

The question becomes 384 local numbers. The nearest passages and the best keyword hits are fused. Only the similarity floor drops vector hits. Default pool: 30.

Judge

Jev, off this machine

Each passage is sent to OpenRouter. Scores under 0.20 are dropped. If the best score is under 0.35, Needle rewrites the query once, widens the pool to 40, and tries again.

Write and check

Two models

The writer drafts from the parent sections. A different checker model then drops sentences that the passages do not support. Citations, quotes, and numbers are checked in code first.

The last check

A draft is not the same thing as an answer you are allowed to see. A second call reads the question, the passages, and the draft, then votes on three things.

Show it

Grounded, safe, and relevant. The answer is saved with its sources, and you can open each citation in the evidence panel.

Is it grounded, safe, and relevant?

Hold it back

If the no-answer setting is on, you see a clear refusal instead of a guess. The attempt is still counted, so Analytics can show knowledge gaps.

Grounded

The factual claims are supported by the passages that were just retrieved.

Safe

The draft is not abusive, dangerous, or deceptive.

Relevant

It actually answers the question you asked.

Keeping the library consistent

Search always reads one published index. A refresh does not edit that index in place. It builds the next one, checks the copy, then swaps the pointer.

RefreshVersion handoff
1

Build beside the live index

A new collection is created and every passage is embedded again with the current model.

↓
2

Count the copy

If the new index does not contain the same number of pieces, the handoff is cancelled and the old index stays active.

↓
3

Publish

The registry flips the new version to active and retires the previous one. The top bar shows that version id.

DeleteIt leaves every copy
1

Vectors

The document is removed from every index version that is not already marked failed.

↓
2

Words and parents

Keyword rows and parent text are deleted, and the file is marked gone so it cannot reappear in the library list.

↓
3

The original file

If an original was stored, it is removed too. A run named “Deletion propagation” is written to the pipeline page.

Trust boundary

Stays here

Files and vectors

Originals, the vector index, the keyword index, and embeddings from all-MiniLM-L6-v2 stay on this machine.

Leaves · Jev

Passage scores

The question and each candidate passage are sent to OpenRouter so Jev can score usefulness. Default model: typesafe/jev-1.13.

Leaves · writer and checker

Two different calls

The writer receives the kept parent sections. The checker, CHECKER_MODEL, receives the draft and those same sections. They are not the same request.

Needle architecture, drawn from the running app. Numbers such as top-k 15, similarity 0.30, and Jev 0.20 are the defaults. Settings can change them for the next question.
